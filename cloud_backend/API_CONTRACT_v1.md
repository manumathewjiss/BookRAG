# BookRAG Cloud API v1

Base path: `/api/v1`. JSON uses UTF-8. This contract is for the Next.js frontend and is versioned separately from the Python implementation. All protected routes require `Authorization: Bearer <Supabase access token>`. The backend validates that token with Supabase Auth; it never accepts a user ID from the browser. Browser cross-origin requests require an allowed origin configured on the backend.

## Common errors

`{ "error": { "code": "short_machine_code", "message": "Safe user-facing text" } }`. HTTP 400 for invalid input, 401 for missing/invalid token, 404 for another user's or nonexistent document, 409 for a document still processing, 413 for an oversized PDF, 429 for daily/per-minute/estimated-usage limits, and 503 for a temporarily unavailable provider. Browsers block disallowed origins through CORS; origin is not an authentication mechanism. No credentials or raw provider prompts appear in errors.

## Routes

| Method and path | Request | Response |
| --- | --- | --- |
| `GET /api/v1/health` | none | `{ "status": "ok" }` |
| `GET /api/v1/me` | Bearer token | `{ "user_id": "uuid", "daily_questions_used": 0, "daily_uploads_used": 0 }` |
| `POST /api/v1/documents` | `multipart/form-data`, field `file` (PDF), optional `title`; maximum configured bytes | 202 `{ "document": Document }` |
| `GET /api/v1/documents` | Bearer token | `{ "documents": [Document] }` |
| `GET /api/v1/documents/{document_id}` | Bearer token | `{ "document": Document }` |
| `GET /api/v1/documents/{document_id}/pdf` | Bearer token | `application/pdf` bytes, private/no-store; 404 for another user's or deleted file |
| `DELETE /api/v1/documents/{document_id}` | Bearer token | 204 on deletion; 404 for deleted, nonexistent, or another user's document |
| `POST /api/v1/documents/{document_id}/chat` | `{ "question": "8–1200 characters", "answer_language": "en|hi|sa|es|ta|te|ml|bn" }`; language defaults to `en` | 200 `Answer` |
| `POST /api/v1/documents/{document_id}/question-preview` | `{ "question": "8–1200 characters", "question_language": "hi|sa|es|ta|te|ml|bn|fr|it|gu|kn" }` | 200 native script, English meaning, detected language, optional mismatch warning, and a confirmation token only when the question is clear and matches the selected language |

`Document`: `{ "id": "uuid", "title": "string", "filename": "string.pdf", "status": "queued|processing|ready|failed", "is_sample": false, "page_count": 0, "passage_count": 0, "error": null, "created_at": "ISO-8601", "updated_at": "ISO-8601" }`. `error` contains a safe short message only. Poll the document route while status is queued or processing. Chat is allowed only when ready. A configured, ready shared sample has `is_sample=true` for visitors other than its owner; visitors may ask about it and see page numbers with short excerpts, but cannot access the PDF or delete it. It is disabled unless `GUEST_SAMPLE_DOCUMENT_ID` and matching `GUEST_SAMPLE_SHA256` are set.

If an embedding request has an uncertain outcome after a worker crash or timeout, document status becomes `failed` with a short review message. The server does not automatically repeat that potentially billable batch; operator recovery happens outside the public API.

`Answer`: `{ "answer": "string", "enough_evidence": true, "evidence_status": "direct_answer|nearby_only|absent|unverified", "citations": [Citation], "timings_ms": { "search": 0, "rerank": 0, "answer": 0 }, "usage": { "input_tokens": 0, "output_tokens": 0, "estimated_usd": 0.0 }, "reused_answer": false }`. `unverified` means Sol claimed support but returned no valid passage citation; the answer is withheld. When the same authenticated user repeats the same question about the same PDF, the server returns the previously saved answer and citations unchanged with `reused_answer=true`. The match ignores surrounding whitespace, one trailing question mark, and apostrophe glyph differences. Any other difference, including tense, case, pronouns, and punctuation, runs the normal retrieval pipeline. Reused responses report zero hosted usage and lookup-only timings; they still count toward daily question limits. Saved answers are scoped to one user, one document, one file digest, and the strict pipeline version. Older rows saved with a previous canonicalizer stay in the table and are not reused. Rows are removed when the document is deleted. Strict saved answers use `004_saved_answers.sql`. Question-language previews additionally require `005_question_previews.sql` before deployment.

`Citation`: `{ "passage_id": "uuid", "pdf_page": 1, "excerpt": "verbatim supporting text" }`. For a shared sample visitor, the excerpt is limited to a short source snippet; their own PDFs retain full citation passages and page viewing. PDF pages are one-based values from extraction metadata, never generated by Sol. Passage IDs must belong to the selected document and must be among the five passages sent to Sol. When evidence is insufficient, `enough_evidence=false`, `citations=[]`, and the answer states what cannot be confirmed. A related page is not presented as proof of a document-wide absence.

`usage.input_tokens` and `usage.output_tokens` are the Sol token counts for a newly generated answer, or zero when a saved answer is reused. `usage.estimated_usd` estimates the Voyage embedding, Voyage rerank, and Sol answer for a miss, and is zero on a hit. A miss replaces the $0.05 reservation with that estimate. A provider timeout keeps at least the reservation. These fields are informational, not an account billing cap.

Initial trial limits are configurable on the server: five uploads/day, 50 questions/day, 10 questions/minute, and $5/day estimated usage per user. A question reserves $0.05 of that estimate before making hosted calls. These are application controls; the provider account must have its own billing controls.

Auth account creation and sign-in remain in Supabase Auth/Next.js. The backend owns token verification and user-scoped data access. The PDF viewer fetches the private source file with the same bearer token used for document and chat requests. No browser cache or public storage URL is required.

## Answer language

`answer_language` defaults to `en` for existing clients. Supported choices are `en` (English), `hi` (Hindi), `sa` (Sanskrit), `es` (Spanish), `ta` (Tamil), `te` (Telugu), `ml` (Malayalam), and `bn` (Bengali). The response echoes `answer_language`. The same PDF retrieval and citation validation run for every choice; the model writes only the answer in the requested language. Source excerpts and PDF page numbers remain in their original form. Saved answers use distinct pipeline versions by language, with the existing English version preserved. This needs no database migration. The frontend remembers the choice per user in that browser.

## Question language preview

For non-English questions, the frontend asks for a preview before chat. The selected language guides romanized-text interpretation; the preview shows native script and English search meaning for user confirmation. A preview marked uncertain cannot be submitted. The backend signs the confirmed question, language, document, owner, document digest, and English meaning for ten minutes; chat rejects missing or altered tokens. Retrieval uses the confirmed English meaning, while the answer model sees both original and English question. The saved-answer namespace includes the question language and confirmed English meaning. English questions retain the existing path and keys. Migration `005_question_previews.sql` adds a separately metered `question_preview` usage operation; previews have a per-user daily and minute limit and count toward spending caps. An unused preview still incurs its model cost.

## Voice question transcription

`POST /api/v1/documents/{document_id}/transcribe-question` accepts an authenticated multipart upload with `file` and `question_language`. The PDF must be visible to that user and ready. Audio must be WebM, Ogg, or MP4 and at most 1 MB. A recording is sent to OpenAI `gpt-transcribe`; the response includes `text`, `detected_language` (nullable), and `language_mismatch`. The transcript fills the editable question box; it is never asked automatically. A known mismatch must be resolved before confirmation. Non-English questions still require the script and English-meaning review. Transcription shares the existing preview count and spending controls, with a conservative $0.01 usage hold per successful request. Audio is not saved in the BookRAG database or PDF storage.
