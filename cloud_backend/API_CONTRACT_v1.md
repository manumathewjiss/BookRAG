# BookRAG Cloud API v1

Base path: `/api/v1`. JSON uses UTF-8. This contract is for the Next.js frontend and is versioned separately from the Python implementation. All protected routes require `Authorization: Bearer <Supabase access token>`. The backend validates that token with Supabase Auth; it never accepts a user ID from the browser. Browser cross-origin requests require an allowed origin configured on the backend.

## Common errors

`{ "error": { "code": "short_machine_code", "message": "Safe user-facing text" } }`. HTTP 400 for invalid input, 401 for missing/invalid token, 404 for another user's or nonexistent document, 409 for a document still processing, 413 for an oversized PDF, 429 for daily/per-minute/estimated-usage limits, and 503 for a temporarily unavailable provider. Browsers block disallowed origins through CORS; origin is not an authentication mechanism. No credentials or raw provider prompts appear in errors.

## Routes

| Method and path | Request | Response |
| --- | --- | --- |
| `GET /api/v1/health` | none | `{ "status": "ok" }` |
| `GET /api/v1/me` | Bearer token | `{ "user_id": "uuid", "daily_questions_used": 0, "daily_uploads_used": 0 }` |
| `POST /api/v1/documents` | `multipart/form-data`, field `file` (PDF), optional `title`; maximum configured bytes | 202 `{ "document": Document }` |
| `GET /api/v1/documents` | Bearer token | `{ "documents": [Document] }` |
| `GET /api/v1/documents/{document_id}` | Bearer token | `{ "document": Document }` |
| `GET /api/v1/documents/{document_id}/pdf` | Bearer token | `application/pdf` bytes, private/no-store; 404 for another user's or deleted file |
| `DELETE /api/v1/documents/{document_id}` | Bearer token | 204 on deletion; 404 for deleted, nonexistent, or another user's document |
| `POST /api/v1/documents/{document_id}/chat` | `{ "question": "8–1200 characters" }` | 200 `Answer` |

`Document`: `{ "id": "uuid", "title": "string", "filename": "string.pdf", "status": "queued|processing|ready|failed", "page_count": 0, "passage_count": 0, "error": null, "created_at": "ISO-8601", "updated_at": "ISO-8601" }`. `error` contains a safe short message only. Poll the document route while status is queued or processing. Chat is allowed only when ready.

If an embedding request has an uncertain outcome after a worker crash or timeout, document status becomes `failed` with a short review message. The server does not automatically repeat that potentially billable batch; operator recovery happens outside the public API.

`Answer`: `{ "answer": "string", "enough_evidence": true, "evidence_status": "direct_answer|nearby_only|absent|unverified", "citations": [Citation], "timings_ms": { "search": 0, "rerank": 0, "answer": 0 }, "usage": { "input_tokens": 0, "output_tokens": 0, "estimated_usd": 0.0 }, "reused_answer": false }`. `unverified` means Sol claimed support but returned no valid passage citation; the answer is withheld. When the same authenticated user repeats the same question about the same PDF, the server returns the previously saved answer and citations unchanged with `reused_answer=true`. The match ignores surrounding whitespace, one trailing question mark, and apostrophe glyph differences. Any other difference, including tense, case, pronouns, and punctuation, runs the normal retrieval pipeline. Reused responses report zero hosted usage and lookup-only timings; they still count toward daily question limits. Saved answers are scoped to one user, one document, one file digest, and the strict pipeline version. Older rows saved with a previous canonicalizer stay in the table and are not reused. Rows are removed when the document is deleted. This release uses `004_saved_answers.sql` and does not require later migrations.

`Citation`: `{ "passage_id": "uuid", "pdf_page": 1, "excerpt": "verbatim supporting text" }`. PDF pages are one-based values from extraction metadata, never generated by Sol. Passage IDs must belong to the selected document and must be among the five passages sent to Sol. When evidence is insufficient, `enough_evidence=false`, `citations=[]`, and the answer states what cannot be confirmed. A related page is not presented as proof of a document-wide absence.

`usage.input_tokens` and `usage.output_tokens` are the Sol token counts for a newly generated answer, or zero when a saved answer is reused. `usage.estimated_usd` estimates the Voyage embedding, Voyage rerank, and Sol answer for a miss, and is zero on a hit. A miss replaces the $0.05 reservation with that estimate. A provider timeout keeps at least the reservation. These fields are informational, not an account billing cap.

Initial trial limits are configurable on the server: five uploads/day, 50 questions/day, 10 questions/minute, and $5/day estimated usage per user. A question reserves $0.05 of that estimate before making hosted calls. These are application controls; the provider account must have its own billing controls.

Auth account creation and sign-in remain in Supabase Auth/Next.js. The backend owns token verification and user-scoped data access. The PDF viewer fetches the private source file with the same bearer token used for document and chat requests. No browser cache or public storage URL is required.
